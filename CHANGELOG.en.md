## [0.9.0] - 2026-10-11

Third review round: discovered configs can no longer set security-sensitive keys, the Action `exec`s the audit so no key-holding parent stays readable, simulated items stay out of SARIF, VH-AI-006 is rewritten for precision and linear time, the deterministic rules disclose files they could not fully scan, VH-AI-009 / VH-AI-007 gaps are closed, and the repository's CI and settings are hardened.

### Added

- `--summary-json PATH` writes a short machine-readable summary after the audit, whatever `--format` is: verdict, exit code, execution mode, model calls per mode (`live` / `simulated` / `invalid` / `cached`), `all_simulated` and the inconclusive reasons; its location is checked before any model call.
- `vibeharness/action_runner.py`: the Action's audit step `exec`s into `python -I -m vibeharness.action_runner`, which runs the CLI in-process and then writes the `verdict` / `exit-code` outputs and the step summary and applies `fail-on`; it emits a `::warning::` when the verdict is `INCONCLUSIVE` but `fail-on` does not fail the job, and when every model call of a hybrid / live run was simulated (e.g. a pull request from a fork, which gets no secrets).
- Evidence gap "The deterministic AI security rules could not fully scan N source file(s)": the AST rules of a Python file have a 30 s cap (`_MAX_SCAN_SECONDS_PER_FILE`); a file that exceeds it or fails unexpectedly keeps the hits already found and is listed in `AISecurityStaticScanner.incomplete_files`.
- VH-AI-006 sinks `os.exec*`, `os.spawn*`, `os.posix_spawn[p]`, `pty.spawn` and `loop.subprocess_shell` / `loop.subprocess_exec`, and sink aliases (`r = subprocess.run`, `getattr(subprocess, 'run')`, `functools.partial(subprocess.run, ...)`).

### Changed

- **Breaking**: `extra_params` now reserves every litellm parameter that changes the destination or the credentials (`extra_headers`, `headers`, `apikey`, `token`, `organization`, `model_list`, `deployment_id`, `use_litellm_proxy`, the Azure / Vertex / watsonx / OCI / GigaChat credentials and projects, a caller-supplied client, ...) plus a name-pattern backstop (`is_reserved_extra_param`: `aws_` / `azure_` / `vertex_` / `oci_` / `watsonx_` / `gigachat_` prefixes and names with key, token, secret, password, credential, endpoint, url, proxy or header parts); a config that sets one now exits 5.
- VH-AI-006 without a shell: an interpreter followed by a script path or `-m module` only counts when the script or module itself is tainted; code options (`-c`, `-e`, `--eval`, getopt clusters such as `-ec`, `cmd /c`, `pwsh -Command`) and programs reading tainted standard input (`input=`, `Popen(...).communicate(x)`, `p.stdin.write(x)`) are HIGH; wrappers (`sudo`, `timeout`, `nice`, `env -S`, `xargs -I`, `flock`, `strace`, ...) and runners (`uv` / `poetry` / `pipenv` / `conda` / `pdm` / `npx` / `pnpm` / `yarn` / `npm` / `bun`, `docker` / `podman exec|run` incl. `--entrypoint`, `kubectl exec`, `find -exec`, `script -c`) are skipped by option tables, and `command -v` is a lookup; `sed` / `sqlite3` / `psql` / `mysql` code arguments and git's global `-c` / `--upload-pack` values count; `shell=1` and `**{'shell': True}` mean a shell. New MEDIUM tier: a program that cannot be determined (`TOOL = os.environ.get(...)`) with tainted arguments, or a non-constant `shell=`. `executable='bash'` with a non-shell argv is no longer flagged.
- The evidence gap for findings without a model-generated test says "unverified" instead of "confirmed" when cross-model verification was not applied.
- `--help`, `--version` and `--init-config` are parsed before any dependency loads, so they are fast and work on a broken install.
- JS/TS coverage: `node_modules` is excluded only below the target root (with the explicit include on Node >= 22.5, a target that itself lives under `node_modules` is covered); on Windows the lcov keys are normcased, so case variants of one module merge; the version gate is described correctly (the gate is `--disable-warning`, from 20.11 / 21.3; the lcov reporter exists from 20.10 / 21.2).

### Security

- A discovered `./vibeharness.yaml` / `./.vibeharness.yaml` (no `--config`) that sets a security-sensitive key is refused with exit 5 and a pointer to `--config`: any global `*_bin` (run at start-up: `docker_bin: ./evil.sh` ran even in mock mode), `docker_*` / `node_*`, `sandbox_provider` / `sandbox_node_provider` other than `local_subprocess` / `docker`, `cache_dir`, and a model's `api_base` / `base_url` / `api_key_env` (outside the bundled key variables) / `aws_*` / `extra_params` / any endpoint- or credential-like key; values equal to the bundled defaults are allowed, so an `--init-config` copy still works. A relative `*_bin` (e.g. `./node`) prints a warning even with `--config`.
- The Action no longer keeps a key-holding bash parent around: the audit step `exec`s into the audit process, so a generated test cannot read the keys from `/proc/<ppid>/environ`; every Python helper in the action runs with `-I` (or drops the working directory from `sys.path`), so a `shlex.py`, `yaml.py` or `vibeharness/` planted in the audited checkout is never imported; `fail-on` is validated before the audit, like `sandbox` / `mutation`.
- SARIF omits white-box findings from the simulation engine and breaches derived from a simulated threat (they looked like real alerts in Code Scanning); the run properties count them in `simulated_whitebox_findings_omitted` / `simulated_breaches_omitted`.
- VH-AI-009: the 會 / 已 / 被 / 曾 description exemption needs a code-entity subject (a reader subject such as 你 / 審查者 / AI, or a missing subject followed by 請 / 直接 / 輸出 / 吧, is a claim; 「此…已被視為安全」 is matched); double negations (不得不, 不能不) and rhetorical 何不 / 豈能不 cancel the negation; 時 in 時間 / 時刻 is no condition while 時 followed by an imperative still commands; 若干 / 當前 are no openers and an opener followed by 請 / 務必 no longer governs; the English description exemption is void when the line names an AI / model / reviewer before it or claims the code is clean.
- VH-AI-007: single-label hosts with prod / primary / master / replica / rds / live / prd tokens are no longer development hosts (`admin:admin@prod-db` is reported); an empty host takes the `?host=` query parameter; `$VAR` counts as a template only in upper-case environment style and `{var}` / `{{var}}` / `<var>` only with a placeholder name.

### Fixed

- Executor: a SyntaxError counts as a target load failure only when the innermost frame shows an import (an import statement, an `__import__` / `import_module` / `reload` call, or a `<frozen importlib._bootstrap>` frame) and it names a real `.py` file; the target parsing a real file with `compile()` / `ast.parse()` is now a defect (FAILED), and `importlib.import_module` of a broken module is a load failure. A JS EFBIG system error (`errno: -27`, `code: 'EFBIG'`) from the per-file size cap is a harness error, like Python's `[Errno 27]`.
- Static gate: `_asserts` walks the helper call graph with an explicit stack, so a ~3000-deep helper chain no longer raises `RecursionError` (with a conservative safety net in `check_test_code`).
- Sandbox: local Python / Node children get `TMPDIR` / `TMP` / `TEMP` inside the run directory and Node coverage runs pin `NODE_V8_COVERAGE` there, so a run killed on a timeout leaves no `node-coverage-XXXX` in the host temp directory; Node's code-less "glob is an experimental feature" warning is stripped from coverage-run stderr, so "produced no report" reasons show the real error.
- VH-AI-009 false positives: a do-not-report needs a finding / code object and is not counted when aimed at the frontend, Sentry or logs; 檔案 / 文件 verdicts in file-scanning or KYC app logic count only when the line addresses the reader; generic AI-assistant notes and salutations, and overriding the system prompt (no longer an ignore instruction), need a review-related word; test-call strings and docstring openers are descriptive. VH-AI-007: userinfo stops at the first `?` / `#` unless the colon precedes it, so a colon in a query or fragment is no credential.
- JS/TS extraction: generic parameter lists may hold object types (`function List<T extends { id: string }>`, `server.post<{...}>(...)` routes), class bodies skip `{` type literals inside heritage generics (`extends React.Component<{ n: number }>`), commas inside `<...>` no longer split parameters, and snippets on very long lines are cut at character positions, so minified one-line files keep their symbols instead of tripping the snippet cap.
- Performance on adversarial input: the JS/TS lexer is linear (regex closers from a once-per-line table, `'/['*20000` 52 s -> 0.02 s; memoized type-annotation look-back, `'=>'*20000` 22 s -> 0.03 s; bounded binding annotations, 32 s -> 0.2 s; route chains matched by position); VH-AI-006 builds each scope's index once and caches argv verdicts (4000 sinks: over 120 s -> 0.45 s) and no longer hits `RecursionError` on deep attribute chains; VH-AI-009 prefilters lines by trigger and required words (1 MB of newlines: 4.9 s -> about 0.1 s).

### Engineering

- CodeQL: the workflow moved to `.github/workflows/codeql.yml` (workflow and job names unchanged, since they are required checks), with top-level `permissions: {}`, `security-extended` queries, `timeout-minutes` and PR concurrency with cancel-in-progress.
- `publish.yml`: the GitHub Release body is this version's `CHANGELOG.en.md` section (falling back to generated notes; an existing Release has its notes rewritten).
- Dependabot also tracks the pre-commit hooks; the pre-commit ruff hook is frozen to the v0.16.10 commit SHA.
- Repository settings: `master` requires a PR and 16 checks including CodeQL, merges are merge-commit only and merged branches are deleted; only admins can create, move or delete `v*` tags; Actions must be pinned to full commit SHAs; secret scanning with push protection, Dependabot alerts and Dependabot security updates are on.
- The Action and README examples pin `github/codeql-action/upload-sarif` to v4.38.3 (the same commit as the CodeQL workflow) and list the `contents: read` / `security-events: write` permissions the job needs.
- New regression suites `tests/test_r3_cli_report_action.py`, `test_r3_executor_sandbox.py`, `test_r3_extractor_scanner.py`, `test_r3_repo_meta.py` and `test_r3_sanitize.py`; the sanitizer time bounds got CI headroom.

### Documentation

- `SECURITY.md` lists 0.8.x as supported and the repository's security features; `CONTRIBUTING.md` documents the required checks, the merge policy and the extended release checklist; README, configuration and design documents describe the discovered-config guard, the `exec` launcher, fork-PR behaviour and the new limits, and the design document's citations refer to the current code.

## [0.8.0] - 2026-10-11

### Added

- JS/TS line coverage: white-box JS/TS tests collect line coverage with Node's built-in coverage (`--experimental-test-coverage`) plus an `lcov` reporter writing into the run directory (the existing spec / junit reporters are unchanged); only the target's own source files count (the generated `test_vh_*` modules, `node_modules` and files outside the target directory are dropped; `/work/<name>` paths inside Docker map back to target-relative paths), and the modules are united (a line any module ran is covered). The result goes into the new `summary.js_line_coverage_pct`, while `line_coverage_pct` still means Python only; an additive field, so the JSON `schema_version` stays `"2"`. The Markdown metric table shows "Python X% / JS/TS Y%" when JS/TS white-box tests exist, and the console adds "行涵蓋率（JS/TS） ／ Line Coverage (JS/TS)". Only files loaded by at least one module count (V8 knows nothing about unloaded files; unlike pytest-cov, which counts never-imported `.py` files as 0%). Needs Node >= 20.11 or >= 21.3 (the lcov reporter); Node >= 22.5 also gets `--test-coverage-include` / `--test-coverage-exclude`; an older or unknown version, every module timing out, or no target file in the reports gives N/A with the reason logged, not an evidence gap. Black-box runs and mock mode collect nothing.

## [0.7.0] - 2026-10-10

Second review round: honest counts and exit codes for pip users, executor attribution and sandbox limits, closed VH-AI-009 / VH-AI-007 gaps with linear-time sanitizers, a JS/TS lexer bounded on hostile input, precise VH-AI-006 argv handling, and PyPI packaging.

### Added

- `vibeharness --init-config [PATH]` writes an editable copy of the bundled config (default `./vibeharness.yaml`) and exits 0; an existing file is kept (exit 5) unless `--force` is given. Without `--config` the CLI uses `./vibeharness.yaml`, then `./.vibeharness.yaml` in the current directory, then the bundled default, and prints the config used and its source on stderr. **Security note**: inside an untrusted checkout this auto-loads the checkout's `vibeharness.yaml`, which can redirect `api_base` / `api_key_env`; pass `--config` explicitly there (the Action always does).
- `python -m vibeharness` (same as the `vibeharness` command); the package ships `vibeharness/py.typed`.
- Action inputs `sandbox` (`local_subprocess` default, or `docker`: builds both sandbox images from the action's own Dockerfiles and runs with a copy of the config set to `sandbox_provider: docker`) and `artifact-name` (default `vibeharness-report`; must be unique per run, e.g. per matrix cell).
- `VIBEHARNESS_KEEP_DUMPABLE=1` keeps the harness dumpable so debuggers can attach (generated tests can then read its `/proc` environ; for debugging only).

### Changed

- JSON report `schema_version` `"2"`: `summary.confirmed_whitebox_bugs` is `null` (not 0, which read as "reviewed, no flaws") when cross-model verification was not applied; the Markdown shows N/A. Version-1 reports are still accepted as `--baseline`.
- `--target` defaults to `.` (the current directory) instead of `examples`.
- Call records carry `attempt` (0 for the first ask, 1, 2, ... for re-asks) and `sorted_call_log` orders by agent, original prompt SHA and `attempt`, so a call's `retried` entries always precede its final record whatever the thread completion order.
- JS/TS test modules are budgeted in groups of 10, each group getting its own `sandbox_timeout_seconds` (worst case ceil(modules / 10) × 2 × `sandbox_timeout_seconds`); Python and JS reruns after a batch timeout use min(`per_test_timeout_seconds`, budget left), so they never exceed the batch budget.
- `--estimate` with `--cache-only` no longer multiplies the maximum by re-asks (there are none); `--cache-only` with `--mode mock` prints a warning that it has no effect.
- The PyPI long description is `README.en.md`; both READMEs use absolute links and lead with `pip install vibeharness-mas` (pipx / uv as alternatives); project URLs, keywords, classifiers and the PEP 639 license expression are set.

### Security

- The composite Action always passes `--config` (the bundled config unless `extra-args` names one), so a `vibeharness.yaml` in the audited workspace is never auto-loaded.
- `extra_params` may not set litellm's canned-response keys `mock_response` / `mock_tool_calls` / `mock_timeout` / `mock_delay` (a fake answer with no network call would be booked as live evidence) or `ssl_verify` (it would make the https check on `api_base` meaningless); both are a `ConfigError` (exit 5).
- Local sandboxes cap every file a child writes at 64 MiB (`RLIMIT_FSIZE`, POSIX; `SIGXFSZ` ignored, so an oversized write gets `EFBIG` and is reported as "not run correctly"), so a print loop can no longer fill tmpfs; captured output is read with `os.pread`. On Windows the fake home also covers `APPDATA` / `LOCALAPPDATA` (`PROGRAMDATA` is kept). The harness is made non-dumpable only when a local sandbox runs, with explicit C types, and a failure is logged at WARNING.
- VH-AI-007: URL credentials are found by a per-`://` scanner, so passwords containing `$ ' " { } < > @` are redacted and reported; templates and masks are exempt only when they are the whole password; loopback is parsed with `ipaddress` (`localhost`, `*.localhost`, 127.0.0.0/8, `::1`, `0.0.0.0`; `127.evil.com` is not); stock passwords and user == password are exempt only on loopback or example / development hosts (`example.com` / `.org` / `.net` and subdomains, `*.example`, `*.test`, `*.invalid`, an empty host, single-label names such as `db`). Trade-off: `admin:admin@prod-db` (single-label) is not reported.
- VH-AI-009: a negation counts only right before the phrase or its verb (single characters inside words such as 未來 / 非常 / 特別 no longer suppress a hit); trailing 後 / 則 / 之前 mark a condition only after 如果 / 若 / 當 …, and 嗎 / ? a question only after 是否 …; descriptions and passives after 會 / 已 / 被 / 曾 are excluded; 的 / 這些 may sit between scope words; an English description needs a code subject or clause-initial modal and a clean-input qualifier, so "you must report no findings" now hits.
- Every sanitizer pattern is linear on adversarial input (200-character clause look-back, look-behind token prefixes, private-key blocks stopping at the next `BEGIN`, a non-backtracking channel-tag regex that also catches a tag missing its `>`).

### Fixed

- CLI: the harness is imported lazily inside `main()`'s guard, so an incomplete install or a missing dependency exits 5 with reinstall instructions instead of crashing with Python's 1 (= NEEDS_FIXES), for the console script, `python main.py` and `python -m vibeharness`.
- Executor: during a test, an ImportError / ModuleNotFoundError raised in a target frame (a lazy import of a package missing from the sandbox) and a SyntaxError-family error in a target file are ERROR "target broken", as at collection, not a FAILED defect (a NameError in the target stays FAILED); such a mutant is invalid. `AttributeError: module / type object ... has no attribute ...` raised in the test module and `OSError: [Errno 27]` are harness errors. When the main process's exit status is lost (reaped elsewhere) the sandbox reports 125, never a fake 0; macOS / BSD on Python < 3.13 wait through kqueue before falling back to `waitpid`.
- Code gate: assertions reached through module-level helpers and methods of base classes defined in the same module count.
- JS/TS extraction: template literals use an explicit stack (no `RecursionError` at hundreds of nested `${`); failed JSX attempts share a scan budget of 4 × the file size (at least 256 000 characters) instead of a count of 32, and known TS generic openings are never tried as JSX; generic look-back (512), argument scans (4096) and the total snippet size (16 × the file size + 2 000 000) are capped; an unexpected error in one file, or a file beyond the snippet cap, is listed in `parse_failures` (an evidence gap) instead of aborting the run.
- VH-AI-006: the argv exemption resolves the real program (basename without path or `.exe`, versioned interpreters such as `python3.11` / `node18`, `deno` / `bun` / `pwsh` / `awk`, `ssh`, wrappers `env` / `sudo` / `doas` / `timeout` / `nice` / `nohup` / `xargs` with their options, `sys.executable`, names bound only to string constants or `shutil.which(constant)`, `executable=`); unknown non-literal programs are treated conservatively; `asyncio.create_subprocess_exec` varargs and keyword-only sink arguments (`args=`, `command=`, ...) are checked. One file failing analysis is skipped and logged instead of aborting `scan_files`. Known limits: `os.exec*` / `os.spawn*` are not sinks, `env -S "bash -c …"` is not parsed, constant names are resolved file-wide.
- Black box: a root or wildcard route (`/`, `*`) names a symbol only when quoted or in its full `GET /` form, so "and/or", "1 * 10^6" or "GET /admin" in prose no longer pull in the root route.

### Engineering

- Hash-locked build backend: `requirements-build.in` / `requirements-build.txt` (setuptools, same range as `[build-system]`); the Action installs with `--no-build-isolation` and the CI `package` and release `build` jobs build with `--no-isolation`, so every install and release build is hash-verified. Dependabot tracks the build lock.
- CONTRIBUTING gains the full release checklist and SECURITY a supported-versions table and private reporting; the CHANGELOGs get compare links for every release.
- New regression suites `tests/test_r2_cli_gateway.py`, `test_r2_executor_sandbox.py`, `test_r2_extractor_scanner.py`, `test_r2_packaging.py` and `test_r2_sanitize.py`. Known limit: the docker CLI's host-side output is not capped (the per-file cap applies to local sandboxes only).

## [0.6.0] - 2026-10-10

Review-driven hardening: sandbox isolation and executor attribution, crash exit codes and config validation, honest reporting of unverified hypotheses, more precise deterministic rules and route detection, a second untrusted channel for model output, and a hash-locked, digest-pinned build and release pipeline.

### Added

- `--cache-only`: every model call is served from the response cache only (needs `--cache-dir` or `global.cache_dir`, else exit 5): no provider call, no `max_model_calls` spend, no re-ask, and neither litellm nor an API key is needed. A call the cache cannot answer is handled like an exhausted budget: simulated in hybrid and listed as an evidence gap ("--cache-only: N agent call(s) had no answer in the response cache"; the verdict cannot be `READY_TO_SHIP`), exit 4 in live. `--estimate` with `--cache-only` still lists the calls and notes that no provider is called and nothing is spent (no budget warning).

### Security

- Local sandbox: on Linux the harness makes itself non-dumpable (`prctl(PR_SET_DUMPABLE, 0)`, once, best effort) before the first child starts, so a generated test can no longer read the API keys the harness started with through `/proc/<harness>/environ`; `HOME` (and `USERPROFILE`) point at a per-run fake home (`PYTHONUSERBASE` keeps `--user` installs working, `HOMEDRIVE` / `HOMEPATH` are dropped). Other processes of the same user stay readable, so `local_subprocess` is still not a security boundary.
- `models.<alias>.extra_params` may no longer set reserved litellm keys (`RESERVED_EXTRA_PARAMS`: endpoint, credentials, `model` / `messages`, timeouts, retries, `fallbacks`, `stream`); they bypassed the https check on `api_base` and are now a `ConfigError` (exit 5), and are filtered again at call time.
- The response-cache key includes the endpoint identity (`api_base`, `aws_region_name`, `aws_profile_name`, `api_key_env`), so the same model string pointed at another endpoint or account is never served the previous answer (existing cache entries miss once).
- Second-order prompt injection: threat-model items reach the attack synthesizer in a new `<untrusted_model_output>` channel, and the verifier and test-generator prompts put the reviewer-written finding text in the untrusted channel; forged tags of either channel (any case, attributes, inner whitespace) are neutralized in both.
- Secret redaction (VH-AI-007) adds AWS secret access keys, URL userinfo passwords (including an empty user as in `redis://:pass@`), JWTs, Stripe and Azure storage keys, replacing only the value where a variable name precedes it; development placeholders in URL credentials (loopback host, stock passwords, user equal to password, templates) are still redacted but no longer reported.
- Live HTTP attacks must target the base URL's exact port (scheme default when omitted); another port on the same machine is another service and the test is refused.

### Fixed

- CLI: any unexpected exception, while building or configuring the harness, inside `--estimate` (including an `--output` that cannot be written) or outside every stage, exits 5 and never Python's default 1 (which CI reads as NEEDS_FIXES); Ctrl-C outside the run exits 130; the argparse program name is pinned to `vibeharness`, so Python 3.14 keeps the `vibeharness:` error prefix.
- Config: a `--config` that is a directory, unreadable or binary, and a top level, section or `models` / `agents` entry that is not a mapping are `ConfigError`s (exit 5); an empty `global:` no longer crashes. `per_test_timeout_seconds` and `sandbox_timeout_seconds` treat null / 0 as their defaults (30 / 120) and reject negative or non-integer values; `sandbox_memory_mb: null` keeps 2048 (only an explicit 0 disables the cap); `docker_pids_limit` null / 0 map to 256 (Docker reads 0 as unlimited; -1 stays unlimited). A null `timeout_seconds`, `max_retries`, `max_output_tokens` or `retry_invalid_output` means the same as leaving it out, the default (180, 2, 16384, 1; a per-model `max_output_tokens: null` keeps the global value), and `timeout=None` (no limit to litellm) is never passed; a zero or negative `timeout_seconds` is still a `ConfigError`. `extra_params` may not set the output-token caps `max_tokens` / `max_completion_tokens` / `max_output_tokens` either (they would override `max_output_tokens`, so `--estimate` and the cache key would see the wrong cap); the error points at `max_output_tokens`.
- Gateway: a re-ask after a fallback answer starts from the primary model again instead of calling the fallback twice. An answer that only became usable after a re-ask is also cached under the original prompt's key (it used to be stored only under the re-ask prompt's key, which depends on the unusable first answer, so a re-run could never hit on its first attempt).
- Without cross-verification `confirmed_whitebox_bugs` is 0: the console and the Markdown report show N/A with the number of unverified hypotheses, the finding list is headed "Unverified Defect Hypotheses (cross-model verification not applied)", and SARIF white-box results carry `properties.verified` and an "Unverified hypothesis" message prefix.
- Dedup is complete-linkage instead of union-find, so a generic finding can no longer chain distinct defects together; findings with fewer than three key terms are compared by Jaccard, and a terse finding merges with a detailed one only when its specific terms all appear in that finding's title. Verifier agents sharing a model alias vote once, and corroborations alone no longer count as verification.
- Sandbox: output goes to temp files instead of pipes and only the main process is awaited, then the rest of the process group is killed (POSIX), so a stray child holding stdout no longer turns a finished run into a timeout or outlives it; stdin is `/dev/null`; a non-positive per-run timeout falls back to the batch budget and timeout reasons name the timeout actually used (never "0s").
- Executor: a NameError / ImportError is a harness error only when the innermost frame is the generated test module; raised inside the target it is a defect (FAILED, not an exploit). JS/TS modules run on the remaining batch budget (`sandbox_timeout_seconds`) and, after a batch timeout, the rest re-run on `per_test_timeout_seconds` within the batch budget, as documented. Node 22's `TypeError [Error]: x` is normalized to `TypeError: x` (`ERR_*` codes kept).
- Code gate: every `test_` method of a `Test*` class must assert, directly or through a `self.<helper>()` that asserts; one asserting method no longer vouches for its siblings.
- JS/TS extraction: quoted strings and regex literals end at a line break, JSX apostrophes and `</tag>` / `/>` no longer swallow later declarations, `${...}` substitutions are lexed as code, `a++ / 2` is division, TypeScript return types, generics, typed arrows and annotated variables are handled, and overload / `declare` signatures are not symbols. Routes need a known router (common names, `*Router` / `*App` names, or a variable bound to `express()` / `Router()` / `fastify()` / `new Koa()` / ...) or a `/` path plus a handler; HTTP clients (axios, `axios.create()` results, `$`, msw `rest`, ...) never count; `""`, template and identifier paths, `app.all`, chained `app.route('/x').get().post()`, object-form `server.route({method, path})`, hapi's array form `server.route([{...}, {...}])` (one route per object), regex paths with a handler on known routers (`app.get(/^\/users\/(\d+)$/, h)`) and Next.js `export { h as GET }` are recognized; `app.get(PATH)` without a handler is intentionally not a route (Express reads a setting with it); a Next.js handler is reviewed once. In `.js` / `.jsx` / `.mjs` / `.cjs` / `.tsx` files a JSX element in expression position is parsed as JSX and its child text blanked, so a `/*`, a lone backtick or a quote in JSX text no longer hides the rest of the file; a `<` that is not valid JSX (a TS generic) falls back to plain lexing, with at most 32 failed attempts per file to avoid quadratic time.
- Python extraction: router receivers are checked before the path (`@router.get("")` on an `APIRouter(prefix=...)` is a route), definitions under module- and class-level `if` / `try` / `with` / `for` / `while` / `match` are extracted, and route-decorated handlers nested in functions (a Flask `create_app` factory) become routes; in the enclosing function's source their bodies collapse into a one-line placeholder naming the file lines, so each body is reviewed once.
- VH-AI-004: `pipeline()` reads `model=` or the second positional argument; `revision="main"` / `"master"` / `"HEAD"` / ... is not pinned; local checkpoints resolve next to the scanned file. VH-AI-005: ambiguous suffixes need an AI receiver, matched on name words (`blockchain_client` is not `chain`); `messages.create` / `messages.stream` / `chat.complete` on a parameter or unknown receiver in an AI-importing file are flagged; `config=` / `generation_config=` count as a cap only when they contain one. VH-AI-006: follows `for` / `with` / comprehension / walrus bindings and dotted attributes; a literal argv list without `shell=True` is safe unless `argv[0]` is tainted or a shell / interpreter; a name the same scope only ever binds to a literal list (`cmd = ["git", "checkout", branch]; subprocess.run(cmd)`) gets the same exemption, while mutating it with tainted data through `append` / `extend` / `insert` / `+=` fires; new sources (`llm(...)`, `llm.predict`, `LLMChain().run`, `ollama.chat`, `chain.invoke`, ...) and sinks (`subprocess.getoutput` / `getstatusoutput`, `asyncio.create_subprocess_shell` / `_exec`), so `answer = llm(...); eval(answer)` now fires.
- VH-AI-008: Hangul fillers are HIGH (shown as `<U+XXXX>`), invisible formatting characters MEDIUM; ZWJ / ZWNJ and U+FE00–FE0F are MEDIUM except in emoji, RTL / Indic and CJK-variant contexts (a run of selectors is byte smuggling); LRM / RLM / ALM and Mongolian free variation selectors are only stripped.
- VH-AI-009: matched after NFKC normalization; detects "ignore everything above" and phrases split across two comment or prose lines (adjacent code lines are never joined); English descriptions of behaviour ("should report no findings for clean code") are skipped; Chinese verdict claims must name the code object and have no negation or condition, empty-report phrases must be commands; digit counts (「回報 0 個漏洞」) and low-false-positive Chinese phrases dropped earlier are recognized again.
- Black box: threat ids outside `[A-Za-z0-9_.:-]{1,40}` are renumbered `THREAT-NN`; STRIDE categories parse case- and separator-insensitively and threat severities are stripped and upper-cased; crashed threat-modeling batches and attack syntheses are booked through `record_failure` (evidence gap #3).
- Reviewer severities are normalized (whitespace, punctuation, case, synonyms such as `CRIT`, `SEVERE`, `MAJOR`, `MODERATE`, `MINOR`, `NOTE`). On a live `LLMGatewayError` or Ctrl-C the reviewer, verifier, test-generator, threat-modeling and synthesis pools cancel the calls not yet started, so a failed strict-live run no longer pays for queued calls.
- `en_only` / `zh_only` split only `bi()` output (CJK before, none after the separator), so a live model's text that happens to contain " ／ " is no longer truncated.
- Reports: model-derived ids and paths go through code spans with pipes escaped in tables; model free text has line breaks (including U+2028 / U+2029 / U+0085) collapsed, so it cannot open a spoofed heading, setext underline, HTML or table block. SARIF never emits `..`: absolute paths outside `%SRCROOT%` become `file://` URIs without `uriBaseId`, an escaping relative path gets no location, and Windows drive paths follow `ntpath` rules on any host. A breach is located by whole identifiers or routes, the longest match winning. `summary.agent_calls` and the partial report's `agent_calls` are sorted deterministically.

### Changed (design corrections per OWASP LLM Top 10 2026 / MITRE ATLAS)

### Added (security design)
- **Deterministic AI-security rules `VH-AI-001`–`009`** (`agents/whitebox/ai_static_scanner.py`, no model involved): `trust_remote_code=True`, `torch.load` without `weights_only=True`, pickle-style deserialization, hub models without a pinned `revision`, LLM calls without an output cap, model output flowing into `eval`/`exec`/shell/SQL, hard-coded credentials, invisible/bidi control characters, and comments addressing AI reviewers. - **Untrusted-code channel (LLM01:2026, AML.T0051.001)**: code shown to any model has invisible characters stripped and secrets redacted (LLM02:2026, AML.T0055), is wrapped in `<untrusted_target_code>` (a forged closing tag is neutralized), and every code-reading agent's system prompt carries a security policy; planted reviewer instructions or invisible characters are an evidence gap, so such a run can never be `READY_TO_SHIP`
- **OWASP LLM Top 10 2026 threat modeling**: `threat_rules.yaml` gains `owasp_llm_top10_2026` (ATLAS tactic/technique and CWE mappings); it is applied automatically when the target imports an AI SDK, threats gain an `atlas_mapping` field, and the report's threat table a MITRE ATLAS column

- **Generated tests may not install packages** (slopsquatting, LLM04:2026, AML.T0060): `pip install`, `import pip` and the like are refused by the static gate
- **Model endpoints must be https** (plain http only for loopback); a bad `api_base` fails at startup with `ConfigError`. Every model call records a `prompt_sha256` for audit traceability
- Reviewers may report an optional `owasp_mapping`; reports list the reviewer models and the detected AI components

The per-request `timeout_seconds` likewise rises from 60 to 180, since Opus took longer than 60s to write a long threat-model JSON. - **Reports keep the generated test code** (audit trail): the Markdown report gains a "Generated Test Code" appendix listing each white-box / black-box test's code, its source finding / threat and its outcome in collapsible blocks; the JSON report gains `generated_tests` / `blackbox_generated_tests` with the code verbatim. - **Unusable answers are re-asked**: a live answer that is not JSON, lacks a key or is empty used to be booked `invalid` and turned the whole run INCONCLUSIVE; it is now re-asked `global.retry_invalid_output` times (default 1) with a prompt naming the problem and demanding JSON only. The first attempt is booked `retried` (shown as "unusable, re-asked" in the Execution Provenance table, not an evidence gap) and only a still-unusable answer is booked `invalid`; every re-ask is a real call against `max_model_calls`, none happens once the budget is spent, and `json_output=False` repair calls are never re-asked
- **`models.<alias>.extra_params`**: parameters passed verbatim to litellm (e.g. `thinking: {type: disabled}`, `reasoning_effort: low`) so a reasoning model does not spend the whole `max_output_tokens` thinking (the main GLM failure in live runs); validated as a mapping at start-up
- **File selection**: CLI `--include GLOB` / `--exclude GLOB` (repeatable, replacing the config's `global.include` / `exclude`) and `--changed-since <git ref>` (only files that changed relative to that ref, staged, unstaged and untracked included; an unresolvable ref or a target outside a git repository is exit 5); filtered-out files are not evidence gaps. `site-packages` joins the skipped directories
- **`global.max_file_bytes`** (default 1 MB): larger files (minified bundles, generated code) are not analyzed and are listed as an evidence gap; the character-by-character JS/TS lexer used to take minutes on them
- **Run metadata in reports**: `summary.run` carries `generated_at` (UTC), `harness_version`, `execution_mode`, `config_path`, `sandbox_provider`, `target_path`, `target_git_commit` / `target_git_dirty` and `file_filters`; shown in the Markdown header, the JSON report and the SARIF run `properties`; JSON gains `schema_version` (`"1"`)
- **Fail early, interrupt cleanly**: a missing or unwritable `--output` / `--sarif` directory exits 5 before any model call (the run used to crash while writing the report, after every model call had been paid for); Ctrl-C exits 130 with a note that no report was written instead of a traceback

### Fixed (deep review, 2026-10-09)
- **Import guidance for package targets**: when `--target` is a directory that is itself a package (has `__init__.py`, modules use relative imports), prompts and offline probes said `from app import f`, the target raised `attempted relative import with no known parent package` on execution, and the executor blamed it on "the target is broken"; `module_import_name` now detects the package and anchors at the parent directory (`from shop.app import f`; the parent is on the sandbox's sys.path already), and probes load the target with `importlib.import_module`
- **`--base-url` accepts http(s) only**: `urllib` opens `file:` / `ftp:` / `data:` URLs too, so `--base-url file:///etc/hostname` once counted as a live server and switched into Live HTTP mode; the CLI and `ThreatScenarioBuilder` now check scheme and host with `validate_base_url`, and an invalid URL is a usage error (exit 5)
- **`VH-AI-009` no longer treats a bare `READY_TO_SHIP` as injection**: the rule fired 27 times on this repository's own code (all verdict constants), and any target that reads the JSON report and compares `overall_status` would be an evidence gap forever; it now matches only sentences that ask the reviewer to produce that verdict, and a dogfooding test scans the harness's own sources for zero hits
- **Provider error text is redacted before it is recorded**: the raw `live invocation failed: …` text went into the `call_log` reason, the Markdown Execution Provenance table, the JSON report and live-mode stderr, while an HTTP client exception can echo a URL or header carrying the API key; every reason and `LLMGatewayError` message now passes through `redact_secrets` and control-character stripping
- **Numeric settings are validated at start-up**: `timeout_seconds`, `max_retries`, `max_output_tokens` (global and per model) and each agent's `temperature` were read only when a call was made, so a typo (e.g. a string) made litellm fail and hybrid mode quietly fell back to the simulation engine, leaving just an INCONCLUSIVE verdict; they are now `ConfigError` (exit 5)

### Fixed (gaps listed by the design document)
- **Crashed reviewer / verifier batches are evidence gaps**: when a batch raised outside the gateway, it was only logged and treated as an empty result, with no `call_log` entry, so the gate could not see the missing review; `LLMGateway.record_failure` now books it as an `invalid` call (reason includes the exception), and the evidence-gap message lists each agent with its reason
- **A single reviewer model is an evidence gap**: with every `whitebox_reviewer_*` on the same model the console only warned; the run now also records it in `inconclusive_reasons` (never `READY_TO_SHIP`; OWASP LLM07:2026)
- **Report sanitization completed**: the Markdown evidence-gap list and the "Threats Not Tested" list bypassed `markdown_safe` / `_code_span`, so a model-chosen threat id or failure text could inject images, HTML or break out of a code span
- **Agents without `model_alias` show as `unconfigured`**: reviewers and verifiers used the agent-id suffix as the alias (the report named a model that was never called, and the debater's self-review exclusion compared the wrong alias); they now resolve like the gateway routes them, with finding ids `WB-UNC-NN`
- **`max_files` validation in the config**: a negative, boolean or non-integer value is now a `ConfigError` (exit 5), like `max_model_calls` / `max_concurrent_calls`; a negative value used to be taken as a slice and a string was silently converted by `int()`
- **Two Docker tests failed when the suite ran as root**: the tests now create the run dir first (the real path always `mkdtemp`s it), and a new test with a faked uid covers the root branch that opens the run dir to `nobody`

## [0.2.0] - 2026-10-07

Packaging, model-output robustness, execution correctness and SARIF fixes from a deep review, plus parallel test synthesis and a cost guard; a second verification round adds execution-attribution honesty, gate decoy protection and engineering convergence; a third hardening round covers stricter mypy, CI supply-chain protection and a higher coverage floor.

### Added
- **JS/TS extractor rewrite** (PR #19): a dependency-free lexer with real brace/parenthesis matching — strings, template literals (including nested `${}`), comments and regex literals are masked first, so their contents can no longer create phantom declarations; functions, arrow functions and routes get accurate line spans (the old fixed 15/25-line windows truncated long functions and duplicated neighbours); generators, async, multi-line signatures, bare-parameter arrows and class methods (constructor/static/async; `if`/`while` are no longer mistaken for methods) are supported; routes accept any receiver (app/router/server/fastify…) with string or template-literal paths, and Next.js App Router handlers named after HTTP verbs are marked as routes
- **Parallel white-box test generation and black-box attack synthesis**: model calls fan out on a thread pool like the review/verification phases, with deterministic output order (test ids, reports); one failing finding/threat no longer takes down the others (live mode still fails loudly)
- **Parallel threat modeling across symbol batches**: `AutomatedThreatModeler` batches fan out concurrently on a thread pool, eliminating the Phase 4 serial bottleneck on large targets while preserving deterministic output
- **`max_model_calls` cost guard** (CLI `--max-model-calls`): caps real model invocations per run, exact under concurrency; when exhausted, hybrid falls back to simulation and lists an evidence gap (never `READY_TO_SHIP`), live fails
- **Tunable limits**: `max_concurrent_calls` (parallelism) and `max_files` (CLI `--max-files`, previously hard-coded to 50)

### Fixed
- **Determinism and precision of review, dedup and black-box synthesis** (PR #18): dedup uses transitive union-find, sorted corroborator lists and finding_id tie-breaks at equal severity, and plural stemming no longer mangles `classes`/`address`; symbol matching prefers an exact name before a suffix, and a finding that names no symbol stays unresolved instead of being pinned to the batch's first symbol; finding ids are numbered per reviewer agent and de-duplicated, so two agents sharing a model alias cannot collide; black-box symbol relevance uses whole-word matching (`username` no longer pulls in `get_user`), and in live mode attack code targeting a host other than the base URL is rejected statically; `render_symbols` truncates over-budget blocks instead of dropping them; the report shows an UNKNOWN badge for an unrecognized `overall_status` and renders a list field mistakenly returned as a string as one item instead of character by character
- **`pytest.fail` security exploit misclassification**: `_is_assertion` now recognizes `Failed:` messages emitted by `pytest.fail()`, correctly confirming security exploits instead of demoting them to `INCONCLUSIVE`
- **Multi-tier LLM JSON parsing fault tolerance**: `_clean_and_parse_json` now handles conversational text wrapping, case-insensitive and unclosed code fences, and multi-block candidate recovery, avoiding spurious `invalid` calls
- **Installed package could not run**: the wheel did not ship `config/agents_config.yaml` / `threat_rules.yaml`, so a `pip install`ed `vibeharness` always failed with "Agent config not found" (exit 5); they are now installed with the package. Missing or broken threat rules now log a warning instead of being skipped silently
- **A `null` model field crashed the whole pipeline**: the test generator and attack synthesizer raised `ValidationError` on `"title": null` and other non-string fields; they now fall back to defaults. Reviewer fields are coerced the same way; only findings with neither a usable title nor description are dropped
- **Generated tests with `from __future__` imports always ERRORed**: the harness header is now inserted after the docstring / `__future__` imports
- **Threats were not deduplicated across batches**: the same threat (STRIDE category + title + attack vector, normalized) is kept once with its highest severity, instead of being synthesized and executed again for every batch
- **Offline probes called argument-less functions**: functions such as `main()` or `run_server()` are no longer invoked by probes (which used to trigger real side effects or hang until the timeout)
- **Black-box testing no longer probes `localhost:8000` implicitly**: `--base-url` now defaults to none; Live HTTP mode only runs against an explicitly given URL, so attack scripts cannot hit an unrelated local service
- **White-box false positives**: a generated test calling the target with the wrong signature (a `TypeError` raised in the test module itself) is now an ERROR, not a target defect that yields NEEDS_FIXES
- **SARIF**: never emits `"locations": null`; unattributed findings (`unknown`) no longer get a fake URI; URIs are relative to the git repository root; rule ids are stable and fingerprints ignore casing/punctuation; black-box breaches are located at the attacked symbol when possible
- **Docker sandbox**: the in-container `timeout` backstop uses the run's own budget (the per-test budget on reruns, not the whole batch budget)
- **Cross-verification**: quoted indices (`"0"`) are accepted and booleans rejected (`True` used to count as index 1)
- **`.gitignore` cleanup**: ignored `.venv/`, `*.sarif`, `report.json`, and cache folders

### Fixed (verification round 2)
- **Honest executor attribution**: a corrupted / unparseable sandbox junit report is reported as "report could not be parsed" instead of "no tests collected"; per-test rerun parse failures are flagged the same way. A target module that crashes on import (syntax error, missing dependency) is now attributed to the target ("Target code is broken and was never exercised by this test", with the real exception text) instead of blaming the test; the test's own import errors still blame the test; generic failure reasons prefer the pytest traceback `E` line
- **Parent-directory module shadowing**: the sandbox sys.path puts the target directory first, so a same-named module in a parent directory no longer shadows the module under test
- **Per-batch verifier isolation**: a non-gateway exception in one cross-verification batch is logged and treated as "no consensus" for that batch instead of aborting arbitration; gateway errors still fail loudly in live mode
- **Threat-rules degradation**: structurally wrong `stride_categories` / `owasp_api_top10` (nulls, non-strings, non-dict entries) degrade safely to no guidance with a warning instead of raising `AttributeError`
- **SARIF home-directory guard**: when the user's home directory is itself a git repo (dotfiles), `sarif_root` no longer treats it as the repo root (comparison via `os.path.samefile` + case normalization), so findings are no longer attached to the dotfiles repo
- **Any-of key validation for LLM responses**: `generate()` accepts `required_keys_any`; the test generator requires `tests` or `code`, so a refusal can no longer silently produce zero tests
- **URL guard resolves IPv6 and userinfo**: `scenario_builder` now uses `urlsplit().hostname` (`[::1]` and credentials no longer mask the host); unparseable URLs fail closed
- **Full traceback on crashes**: unexpected CLI exceptions no longer print a bare `type: message` line
- **Fallback threat ids have no gaps**: model-supplied ids no longer consume the fallback counter, so THREAT-XX numbering stays contiguous
- **Vacuous-test gate decoys**: an `assert` inside a nested, never-called helper no longer satisfies the gate (only helpers actually invoked count); removed the unused `top_level_test_functions`
- **Non-Python targets disclosed and guided**: detected JS/TS is listed as an evidence gap (the sandbox only executes Python, so there is no dynamic verification); `import_instructions` for non-.py files state that the file cannot be imported or executed instead of handing out an importlib recipe that cannot work
- **Misc**: the detected-language list in reports is sorted (deterministic); test-generator self-heal logs identify the finding id instead of an unrelated integer index; the evidence-gap message for clean targets is clearer about which boundaries remain unverified

## [0.1.2] - 2026-10-03

Correctness, honesty and infrastructure sweep from a deep review (PRs #13, #14, #15, #16).

### Fixed
- **Sandbox stability**: after a timeout kill, the pipe drain is bounded, so a grandchild that daemonized into a new session can no longer hang the whole run forever; the timeout sentinel is now 124 (execution failure 125), decoupled from SIGHUP/SIGINT signal deaths
- **Exit-code semantics**: a new usage code 5 covers a missing `--target`, a missing or invalid-YAML config, an unavailable sandbox, CLI misuse, and unexpected crashes; exit 1 is now exclusive to NEEDS_FIXES (CI can no longer misread a harness error as a defect verdict); unknown verdict strings fail closed with exit 3
- **Quality-gate honesty**: black-box attack tests that FAILED without matching the exploit predicate are now counted (`blackbox_tests_failed`) and listed as an evidence gap — previously they vanished, letting a run pass as READY_TO_SHIP; the vacuous-test gate can no longer be fooled by assert-prefixed calls such as `mock.assert_called_once()`
- **Injection hardening**: LLM-controlled metadata in generated-test headers is newline-sanitized so unvalidated code cannot bypass `check_test_code`; fence stripping accepts `python3`/`Python` language tags without leaking the tag into the code
- **Threat-modeling coverage**: target symbols are now batched (same token-budgeted scheme as the white-box reviewers) so large targets are no longer silently truncated to a partial view; threats from all batches merge with deterministic renumbering of colliding ids
- **Cross-verification counts**: confirmed statistics subtract undecided tie findings, matching the consensus summary text
- **Docker sandbox hardening**: a root harness runs the container as `nobody`; `noexec,nosuid` on the `/tmp` tmpfs; an in-container `timeout` backstop so the container dies even if host-side cleanup fails; `custom_env` filters credential keys and interpreter-injection vectors (`BASH_ENV`, `LD_PRELOAD`, ...); only the target's own paths are rewritten for the container
- **Executor**: the JUnit module regex supports ≥1000 modules; malformed container-emitted `time` attributes cannot crash parsing; single-module batch timeouts are reported honestly; batch-timeout reruns are capped by the sandbox budget; partially skipped modules are flagged
- **Misc**: a crashed reviewer batch no longer discards other batches' results (live mode still fails loudly); unknown severity/STRIDE values are logged; the server-health probe retries; non-UTF-8 targets degrade gracefully; PoC fences widen when the code contains backticks; AST extraction reports `*args/**kwargs` and class decorators

### Engineering
- **Dependency locking**: new `requirements.lock` (`uv pip compile --universal --python-version 3.10`, marker-aware across 3.10–3.13); upper bounds on `litellm`/`pydantic`; CI and the sandbox image install pinned versions matching the lock
- **Static typing**: mypy in CI (all 28 findings fixed); mypy added to `requirements-dev.txt`
- **CI hygiene**: `push` fires only for `master` (PR branches no longer run twice); `permissions: contents: read`; `timeout-minutes` on every job; matrix extended to 3.11/3.12 (2 OS × 4 versions); pip cache keyed on the lock
